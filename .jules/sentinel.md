## 2024-05-24 - Fix Insecure YAML Parsing Vulnerability
**Vulnerability:** The codebase consistently used `yaml.load(f, Loader=yaml.FullLoader)` instead of `yaml.safe_load(f)` to parse configuration files (like `kis_devlp.yaml`) and cached token files (`token.tmp`) across multiple authentication modules (`kis_auth.py`, `kis_api.py`, etc.).
**Learning:** `FullLoader` mitigates some risks by disallowing arbitrary object instantiation out-of-the-box compared to the default `UnsafeLoader`, but it can still execute code if explicitly configured or bypassed in certain contexts. The widespread use of `FullLoader` instead of `SafeLoader` suggested a codebase-wide misunderstanding of the secure defaults for `PyYAML`, leading to an unnecessary RCE risk when processing externally-modifiable files.
**Prevention:** Always enforce the use of `yaml.safe_load(f)` (or `yaml.load(f, Loader=yaml.SafeLoader)`) when parsing YAML files that contain only standard data structures (dictionaries, lists, strings, etc.), especially for configuration and cached data. Code reviews and SAST tools (like Bandit or Semgrep) should flag any usage of `FullLoader` or the default `load` as critical findings.
